# 小说精读 + 语音问答

工作区(/Volumes/Data-SSD/coding-space/小说)的用途:导入小说 → 分章精读沉淀笔记 → 用户提问时检索笔记与原文作答 → TTS 把答案读出来 → 每轮问答追加进对话记录,实现跨会话的连续对话。以下相对路径均相对工作区根目录。

## 目录约定

每本书一个目录,位于 `books/<书名>/`:

```
books/三体/
  原文.txt          # UTF-8 全文(导入时统一转码)
  chunks/           # 章节/字数切块文件(长书)
  notes/            # 分块精读笔记(长书才有)
    001.md
  精读总集.md       # 笔记与分析的合并单文件,问答检索的第一入口
  分析/
    人物.md         # 人物档案 + 人物弧线(关系变化、结局)
    情节与时间线.md
    主题与风格.md
    速查索引.md     # 主要人物/关键事件 -> 章节定位,问答的第一入口
  对话记录.md       # 每轮问答追加于此,是连续对话的记忆载体
  问答库/档案.jsonl # 结构化问答存档(id/时间/问题/答案/出处/命中次数),重复问题缓存与答案溯源
```

## 模式一:导入并精读

1. 导入:运行 `python3 .agents/skills/novel-companion/scripts/import_book.py <文件路径> [书名]`,脚本自动识别编码并转 UTF-8。docx/epub 先转 txt(python-docx 或 zip 解包正则去标签)再导入。
2. 精读策略按字数选择:
   - 15 万字以内:直接通读原文,直接写 `分析/` 四件套,不建 notes/。
   - 更长:按"第X章"正则分块,无章节标记则每约 3 万字切一块。逐块精读,每块写 `notes/NNN.md`,固定五栏:本块事件、人物动态(新登场/关系变化/死亡)、伏笔与悬念、重要对话金句、时间与地点线索。
   - 超长(100 万字以上):用并行子代理逐块精读(subagent_antigravity,给块文件路径和上面的五栏模板),自己最后汇总合并。
3. 汇总产出 `分析/` 四件套与 `精读总集.md`;速查索引要保证任何主要人物、关键事件都能定位到章节。
4. 长书精读用 todo_write 跟踪进度。

## 模式二:语音问答(连续对话)

用户提问后,严格按此顺序:

1. **恢复对话记忆(必做)**:跨会话开场(说"继续聊")时读 `对话记录.md` 尾部约 8000 字;同一会话内上下文里已有,不用重读。当前问题的"他/她/那件事"等指代优先用最近几轮问答解释。
2. **查问答库+检索(合并为一次 Bash 调用)**:一条命令里先 `python3 .agents/skills/novel-companion/scripts/qa_archive.py find --book <书名> --query "<问题>" --min-score 0.85`,再 grep `精读总集.md`(全部笔记+分析的合并单文件)和必要时 grep `原文.txt`,多个命令用分号连在同一条 Bash 调用里。
   - **只读检索与阈值复用**: `find` 为只读操作,不写库。若返回相似度 **≥0.85** 的高分候选,**直接复用档案中的答案**秒答播报,不必重新检索;低于 0.85 或问题有新角度时再正常作答。若未匹配但凭上下文怀疑问过,grep `问答库/档案.jsonl` 关键词兜底。
   - 回答必须以检索到的内容为据,给出章节出处。
3. **作答**:口语化纯文本,150~450 字(约 1~1.5 分钟语音)。不用任何 markdown 符号(#、*、列表、表格),TTS 读符号很难听。开头直接回应问题本身。
4. **播报+落盘+归档(一条 Bash 调用完成)**:在同一条命令里:写答案到临时 txt、调 `python3 .agents/skills/novel-companion/scripts/speak.py --rate +10%` 播报(语速快 10%,用户嫌慢时可到 +15%)、`cat >>` 追加到 `对话记录.md`、`python3 .agents/skills/novel-companion/scripts/qa_archive.py add --book <书名> --question ... --answer ... --sources "<章节出处>"` 归档(同题自动去重)。timeout 设 600000——播放是阻塞的。格式:

```markdown
## 2026-08-30 21:32
问:<用户原话>
答:<播报的完整回答>
```

5. 聊天窗口里同时展示文字版回答,方便用户核对与追问。

提速要点:单轮问答的工具调用目标是 **2 次**(1 次查库+检索 + 1 次播报落盘归档);对答案把握不足时允许对原文.txt 再补一次 grep,但不得超过 3 次。不要读整个文件做核对——总集里的笔记已是精读结论,直接引用即可。

答案溯源与修正:用户质疑某个旧答案时,`grep 关键词 问答库/档案.jsonl` 即可查到当时的问题、答案全文、章节出处和存档时间;发现答案有误,使用 `python3 .agents/skills/novel-companion/scripts/qa_archive.py update --book <书名> --id <条目ID> --answer <新答案> --sources <新出处>` 修正档案并在 `对话记录.md` 追加更正记录。

## 模式三:批量缓存生成(批量自进化充库)

固化历史批次生成的标准工作流,用于小说精读后快速填充高频问答库:

1. **分批生成盲区问题**: 针对人物命运与动机、世界观与底层设定规则、关键悬念伏笔与多重反转,规划批次问题清单(每批建议 20~50 题)。
2. **一次集中 Bash grep 取证**: 避免单题碎片调用,单条 Bash 命令集中 grep `精读总集.md`(必要时 grep `原文.txt`)统一取证。
3. **带章节出处作答**: 形成口语化纯文本答案(150~450 字),必须注明精准章节出处;笔记或总集证据不足的标注"待核实",严禁无据脑补。
4. **一次批量归档落盘**: 单条 Bash 命令批量调用 `qa_archive.py add` 写入 `问答库/档案.jsonl`(哈希自动去重),并以 `## YYYY-MM-DD 自进化批量充实缓存库` 追加到 `对话记录.md`(批量任务免播报以提速)。
5. **抽测改写问法验证命中**: 每批完成后随机抽选 2 个问题进行语义改写(调整句式/同义词),用 `qa_archive.py find --book <书名> --query "<改写句>" --min-score 0.85` 验证只读高分命中,确保缓存有效可用。

## 对话记忆规则

- 对话记录.md 是唯一的跨会话记忆;任何一轮语音问答都必须落盘。
- 用户说"继续聊/接着刚才"但本会话没有上下文时:列出 `books/` 下书目,读最近修改的那本的对话记录尾部,接着聊。
- 指代不明且记录尾部解释不了时,先向用户确认指代,不要猜。

## 语音参数

- 运行于 macOS 环境,由 `python3 .agents/skills/novel-companion/scripts/speak.py` 处理合成与播放。
- **在线增强(推荐)**: 支持 edge-tts(`pip3 install edge-tts`),享受微软自然音色。默认女声晓晓 `zh-CN-XiaoxiaoNeural`,可选男声云希 `zh-CN-YunxiNeural`、晓伊 `zh-CN-XiaoyiNeural`。播放调用 macOS 内置 `afplay`。
- **离线兜底**: 未安装 edge-tts 或网络不可用时,脚本自动降级调用 macOS 本地 `say` 命令(系统中文音色如 Tingting)播放,离线即用。
- 语速用 `--rate +10%` 这类写法调整。
- 只存文件不播放:加 `--out 路径.mp3`。
- 语音听写输入: macOS 任意输入框连按两次 `Fn` 键(或 Control 键,视系统设置)启动听写。
